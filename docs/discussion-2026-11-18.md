# 项目讨论记录（2026-11-18）

> 本文整理了项目起步时的讨论：从一道四年级拓展题出发，讨论做一个计数教学工具是否有价值、
> 选什么技术、能否服务美国大学课程与其他国家，以及资金上的现实预期。

## 1. 起点：一道四年级拓展题

四年级老师额外给的拓展卷，第 6 题：

> 数一数图中有 ___ 个三角形。

右图是一条由三角形网格组成的平行四边形长条（照片是斜拍的，按 **3 行、每行宽 7 个单位**理解）。

### 解题思路：分类计数（加法原理）

三角网格里所有三角形都是等边三角形，只有两种方向：尖朝上 ▲ 和尖朝下 ▼。
按“边长 × 方向”分类数，再相加：

| 边长 | ▲ | ▼ |
|---|---|---|
| 1 | 21 | 21 |
| 2 | 12 | 12 |
| 3 | 5 | 5 |
| **合计** | | **76** |

- 容易漏掉的是**大的 ▼**。
- 推广：3 行、宽 n（n ≥ 2）时，总数 = **12n − 8**（n = 6 → 64，n = 7 → 76，n = 8 → 88）。
- 一般公式：宽 w、r 行时，总数 = 2 Σ (w − k + 1)(r − k + 1)，k 从 1 到 min(w, r)。
- ⚠️ 76 依赖于“3 行 × 宽 7”的判断；如果原图宽度不同，套上面的公式即可。

这道题本质上就是组合数学教材 *Counting Rocks!* 第 2 章（加法原理）的内容，
只是换成了小学生能理解的样子。

## 2. 用 C# 做工具有价值吗？

**结论：有价值，前提是做“陪孩子思考的工具”，而不是“答案机”。**

- 价值低的做法：输入图形、直接输出答案。这会替孩子思考。
- 价值高的做法：
  1. **对孩子**：先自己数 → 工具按类别告诉她“边长 2 的 ▼ 还有遗漏”，但不告诉具体数目 →
	 需要时逐个高亮所有三角形。练的是“分类、不重不漏”。
  2. **从数到找规律**：改变图形宽度，看总数每次多几个，自己发现 12n − 8。
	 这就是组合数学的核心方法——**用两种方法数同一个东西**（暴力枚举 vs 公式）。
  3. **对家长**：批量生成变式题和答案，正好发挥计算机专业“枚举 + 验证 + 可视化”的长处。

**原则：目标可以大，起步要小，每一步都踏实可用。**

## 3. 技术选型

候选：Avalonia（桌面应用）、Blazor、C# + React。

| 方案 | 优点 | 缺点 |
|---|---|---|
| Avalonia | 原生桌面应用，Mac 和 Windows 都能跑 | 网页版不成熟；学校常用的 iPad、Chromebook 不方便 |
| **Blazor WebAssembly + PWA** | 发一个链接就能用；GitHub Pages 免费托管；SVG 画图和点选很自然；可以离线、像本地应用一样安装 | 桌面原生体验稍弱 |
| C# + React | 网页生态最成熟 | 一个人维护两种语言，起步负担重 |

**决定：Blazor WebAssembly。** 理由：

- 原来的 Avalonia 项目还是空模板，换掉几乎没有成本。
- 平时在 MacBook 上开发（`dotnet` 命令行 + VS Code 或 Rider），在 Azure 的 Windows 虚拟机上用 Visual Studio，两边通用。
- 女儿在 Mac 上用浏览器打开就能用；老师和学生只需要一个链接，这是“让别人用起来”最关键的一点。
- 核心库是纯 C#，不依赖任何界面框架。以后想做 Avalonia 桌面版，界面层换掉就行，核心不用动。

## 4. 能否对美国大学有用？

**有可能，前提是核心共用、界面分层次。**

- 共同的核心：把被数的每个对象都枚举出来、画出来，再和公式对照。这一点从小学到本科都适用。
- 现状的空缺：大学课程常用 SageMath，算得很强，但不负责“一个个画给你看”；
  商业平台（如 Brilliant）是闭源、收费的。
  **免费、开源、可视化、和教材章节对应的“计数实验室”目前确实是个空位。**
- 要现实：只做数三角形，大学老师不会用。至少要覆盖 *Counting Rocks!* 第 1–7 章的若干核心例子
  （格路径与帕斯卡三角、卡特兰数、递推等），大学用途才成立。

## 5. 联系老师、请求资助

**直接请老师个人捐款，成功率很低，还可能显得唐突。** 更可行的路径：

1. **先做到真正好用**，开源（MIT 协议）、免费。
2. **联系教材作者，只请求反馈，不提钱**。例如 *Counting Rocks!* 的作者
   Maria Gillespie、Rachel Pries、Henry Adams。可以说明“做了与第 X 章对应的交互配套工具”。
   这本书采用 CC BY 4.0 许可，引用习题只需署名；出于礼貌仍应告知作者。
3. **有老师在课上用了，再谈资金**：GitHub Sponsors、Open Collective，
   或与老师合作申请 OER（开放教育资源）经费。这本书本身就是靠 CSU 的 OER 经费写出来的。

注意：Sagan 的 *Combinatorics: The Art of Counting* 是标注“不得传播”的出版前样稿，
**不放进仓库，也不以它为依据联系作者**。

### 现实预期（经验估计，非统计数据）

- 老师个人基本不会付钱；院系一般也不会为免费工具付费。
- 小众教育类开源项目，GitHub Sponsors 常见是每月 0 到几十美元。
- 合作申请 OER 经费最现实，一般是几千美元级别，需要本校老师牵头。
- NSF 等教育经费存在，但需要大学教师做负责人、周期长，属于长期目标。
- 真正有付费意愿的反而是**中国小学奥数、美国竞赛备考（MATHCOUNTS、AMC 8）**的家长市场：
  可以开源核心 + 免费教学版，对题目生成器、可打印练习卷、学习进度跟踪等功能收费。以后再说。

**把预期反过来：不以挣钱为目标，钱是锦上添花。** 更确定的回报：

1. 女儿的数学思维；
2. 一个能体现专业能力的作品集项目；
3. 与大学老师建立联系。

## 6. 扩展到法国、加拿大、英国

**值得做，而且成本比想象的低。**

1. **语言**：英文覆盖美国、英国、加拿大英语区；法文覆盖法国和魁北克。
   界面已支持中文、英文、法文（法文需请母语者校对）。
2. **各国都有对口的使用场景**（以下为经验判断，正式联系前请再核实）：

| 国家 | 小学、初中 | 高中、大学 | 可以合作的渠道 |
|---|---|---|---|
| 英国 | UKMT 数学挑战赛，数图形是常见题型 | 大学离散数学课 | 剑桥大学的 NRICH（免费解题教学网站） |
| 法国 | 袋鼠数学竞赛（Kangourou，发源于法国） | 高三数学专业课程有“组合与计数（dénombrement）” | 中学数学老师社群 |
| 加拿大 | 滑铁卢大学 CEMC 办的 Gauss 等竞赛 | 大学组合数学课 | CEMC（本身就是英法双语） |

   法国最值得注意：计数是高中正式课程内容，不只是竞赛题，使用场景更稳定。

3. **隐私是设计原则**：欧盟和英国有 GDPR，英国还有儿童适龄设计规范，加拿大有 PIPEDA，
   魁北克有 Law 25，美国有 COPPA。
   最简单的应对：**不做账号、不收集任何数据、不加统计分析，进度只保存在孩子自己的浏览器里**。
   现在的版本就是这样做的，以后也坚持。

多几个国家，用户会更多，但收入结构不会变，主要还是靠和老师或机构合作申请经费。

## 7. 已完成（第一个版本）

- `src/CountingArt.Core`：三角网格模型、暴力枚举、公式计算、按“边长 × 方向”统计进度的计数会话。
- `src/CountingArt.Web`：Blazor WebAssembly PWA。
  - 依次点三个顶点“抓”一个三角形；
  - “检查一下”：只说哪一类还有遗漏，不给答案；
  - “看答案”：逐个高亮，并标出漏掉的；
  - 找规律表：宽度每加 1，总数多 12；
  - 中文 / English / Français，语言选择保存在浏览器里。
- `tests/CountingArt.Core.Tests`：28 个单元测试，用暴力枚举和公式互相核对。
- GitHub Actions 自动测试并发布到 GitHub Pages：
  <https://ianhougoodman.github.io/LittleDaughter-TheArtOfCounting/>
- `docs/references/`：收录 *Counting Rocks!*（CC BY 4.0），并说明其他资料的处理方式。
